## 一、虚拟环境（venv）

### 为什么需要虚拟环境

不同项目依赖的包版本经常互相冲突（A 项目要 requests 2.x，B 项目要 3.x）。虚拟环境 = 给每个项目一个**独立的 Python 解释器 + 独立的 site-packages 目录**，装包互不污染，还能锁定版本、复现环境。

### 本机实操记录（已跑通）

```powershell
# 1. 基于 miniconda 的 Python 3.10.20 创建虚拟环境（在仓库根目录）
E:\miniconda3\python.exe -m venv .venv

# 2. 进入环境（Windows PowerShell 语法）
.venv\Scripts\Activate.ps1        # 激活后命令行前缀出现 (.venv)

# 3. 退出环境
deactivate

# 4. 冒烟测试（不激活也可直接调用解释器）
.venv\Scripts\python.exe week1-environment\hello.py
# 输出：total = 15 / 生成器取前 3 个偶数: [0, 2, 4] / 捕获到异常: division by zero / 环境就绪：3.10.20
```

### 关键知识点

| 概念 | 说明 |
|---|---|
| `python -m venv <目录>` | 创建虚拟环境（Python 3.3+ 内置，零依赖） |
| `.venv\Scripts\` | Windows 下环境内的可执行文件目录（python.exe / pip.exe / Activate.ps1） |
| 激活 vs 直接调用 | 激活后 `python`/`pip` 指向环境内版本；不激活则写全路径 `.venv\Scripts\python.exe` |
| pip 安装 | 激活后 `pip install <包>`，只装进当前环境；用 `pip freeze > requirements.txt` 导出 |
| venv vs uv | venv 是 Python 内置、最稳；uv（Rust 写的包管理器）更快、可管 Python 版本，本机暂未装，第1周先用 venv，后续工程化可升级 uv |

### 环境规范（长期遵守）

- 虚拟环境目录 `.venv` 已被 `.gitignore` 忽略，**不提交**进 Git
- 项目依赖清单用 `requirements.txt` 提交，换机器 `pip install -r requirements.txt` 即可复现

## 二、泛读 1：《模型越来越强，企业 AI 为什么还卡在「最后一公里」?》

- 来源：机器之心，2026-09-27（原创）
- 链接：https://www.jiqizhixin.com/articles/2026-09-27-4

### 带读步骤（2026-10-04 完成）

**0. 标题猜主旨**：AI 这么强，企业里怎么还"不好用"？全文回答这个问号。

**1. 背景**：模型突飞猛进（推理/多模态/Agent），但大量企业 AI 仍停在试点演示，没进入业务流程。类比：发动机马力再大，路上全是断头路，车开不进车间。

**2. 核心论点（背这句）**：企业 AI 的核心矛盾从"**有没有 AI 能力**"变成"**AI 能不能低成本、低风险、高效率地嵌入现有业务流**"——模型不稀缺了，稀缺的是怎么放进真实业务还不添乱。

**3. 关键概念：通信是入口**：企业大量业务靠打电话，但通话里的需求/反馈/经验挂断就流失，AI 想用都用不上。
- 快递物流：GPS/电子面单都有，但"失败揽收原因"查不到（原因在快递员与客户的话里）
- 金融保险：人均日外呼 120+ 通、有效转化 <5%，销冠经验留不住
- 汽车销售：判断靠个人经验，无法变成组织能力

**4. 方案与证据（联通云犀，轻量化五道关）**：数据整合 → 智能数析（语音/文本→业务信号）→ 内容生成（标签/建议/报告）→ 场景嵌入（不改员工习惯）→ 安全可控。
- 快递：异常件响应**小时级→分钟级**，签收投诉显著下降
- 金融外呼：人均转化率**×2.3**，新人培训**2周→3天**

**5. 学习关联**：技术底座 = 第5~8周要学的语音转写、RAG、摘要/标签生成、提示词整合上下文。

**6. 一句话总结**：AI 落地难的不是模型，是"把沉睡的数据接进业务流程"——通信数据是入口，轻量化嵌入是答案。

## 三、泛读 2：《Jev 被请下王座，StartLux 中国开源决策模型冲上第一》

- 来源：机器之心，2026-10-03（原创）
- 链接：https://www.jiqizhixin.com/articles/2026-10-03-4

### 带读步骤（2026-10-04 完成）

**0. 标题猜主旨**：Jev 原本排第一，被中国 StartLux 决策模型超了。回答：决策模型是什么？为什么能登顶？

**1. 背景**：Agent 干活时要不断做小而高频的判断（选工具/任务结束没/选 A 还是 B）。每次都调完整大模型 = 又贵又慢，像开航空母舰买菜。

**2. 核心概念：Decision Model vs 普通 LLM**
- 普通 LLM：输入问题 → 生成自然语言文字（写邮件、做规划）
- Decision Model：输入问题+候选选项 → 直接选/打分/判是非（输出"选项2、严重等级3"，不废话）

**3. 成绩数据**：Decision Index 0.2.1 的 38 项基准里 **31 项超 Jev**，综合 **63.88 vs 57.91**；国际象棋 36 局赢 35 局；4B 版单卡 H200 回答 3 问平均 **26ms**；完全开源（0.8B~27B 五档 + 量化）。

**4. 实际用途**：客服工单一次判断"分流团队/处理时效/严重等级"；购物 Agent 逐步判断并下单；团队管理依次选对团队→成员→角色。共同点：**答案空间明确**。

**5. 行业趋势（背这句）**：确定性流程交给代码、搜索交给 Embedding、复杂规划交给 Reasoning 模型、高频小判断交给 Decision 模型——**异构模型分工协作**，而非一个大模型干所有事。

**6. 学习关联**：对应第6~8周本地部署（Ollama+Qwen2.5-7B）与 Agent 架构设计——思考"什么任务用小模型、什么用大模型"。

**7. 一句话总结**：Agent 里最频繁的是候选明确的小判断，专门做判断的轻量决策模型又快又省——模型从"单一大模型"走向"分层分工"。
